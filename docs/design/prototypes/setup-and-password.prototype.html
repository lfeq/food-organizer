Issue #37 on map #31. Throwaway. The two screens the mockup never drew, composed from the components in docs/design/visual-system.md. Three structurally different variants of each; the useful reaction is usually "the header of B with the week-start control of A".

Deviation from the prototype skill's usual shape: both routes sit behind a hard beforeLoad redirect and need a live database, so a ?variant= switcher on the real route would be harder to look at than this. Artboards side by side, like the mockup's own canvas.

Spec over mockup: 1j's own padding (44px/22px), tracking (.18em) and 11.5px note are pre-spec drift; these boards use 40px 24px, 20px gaps, .14em at 9px and 11px mono. Everything the household types is Sans; a masked password is Mono. No shadows anywhere inside a board — the frame shadow is viewer chrome.

What each pair is actually asking. Setup: is first run one form, a guided sequence, or a set of defaults to approve? Password change: does it belong to the sign-in flow, stand as a gate over the app, or shrink to a single revealed field?

Assumptions worth disagreeing with. That setup seeds a starter catalogue at all (the route does not today); that the timezone is detected rather than typed; that the language switcher belongs on both screens; that naming the admin ("papá reset your password") is better than a neutral sentence.
