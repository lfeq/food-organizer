PROTOTYPE — What do the dish catalogue and its add/edit sheet become at both widths?

Issue #84 on map #31. The destination names adding a dish as one of the two flows that must be first-class on a phone, and docs/design/visual-system.md defers per-screen layout to this map. The week screen is settled; the dish flow is not.

The artboard and the code disagree about the catalogue's basic shape. Today src/routes/dishes.tsx renders a three-column grid, one column per course, each row carrying two visible buttons (Edit, and a danger Delete), each column its own add button. 1f renders one list, three mono count chips above it with one active, a single ··· per row, and one course-neutral + Add dish. Three columns cannot survive 390px, so something gives.

The sharpest thing the boards expose is a mutual exclusion nobody has stated. If the chips filter, the desktop cannot keep today's three-column-by-course grid — filtering to Soups leaves one column and two empty ones. If the chips group, the active state in 1f is a lie. The chips decide the desktop layout too, which is why this is one ticket and not two.

Two prior decisions constrain the row. Decide the palette's accessibility floor ruled ··· is a glyph that is the whole control and moved it to --ink-secondary — but not what it opens. What do the interactive states look like? ruled a surface that contains a control is not itself a control, and named the catalogue row as following the day card: it takes no state, and the control inside it carries the affordance. Board D deliberately breaks that, and is labelled with what it costs.

The catalogue is dark territory under the green/dark rule, and 1f obeys it. Nothing in these boards reaches for green except the sheet's selected course segment, which is 1g's own drawing — worth a look, since a course is not the weekly plan either.

ES here is the favourable case. Do the Spanish course labels survive the mono treatment? handed courseSide/courseSidePlural to the build as Guarnición/Guarniciones; src/i18n.ts has not taken it and still ships Acompañamientos, 15 characters. That ticket also already assumed these chips filter ("the real second offender is the catalogue filter chips… intrinsic width, horizontal scroll on the phone") — a prior, not a decision.

Phone — 390px, where three columns die

Four boards, each a different answer to how the catalogue is organised and where a row's actions live. Nine dishes across three courses in every board, so the density is comparable. Where a board opens something, the thing it opens is drawn beside it.

Each board's natural wide form. As with the week stepper, the phone decides and the desktop only has to not fight the choice.
